# 通訊協定筆記：米家電子鍋 mini（`chunmi.cooker.tw1`）

[English](protocol-notes.md)

以下都是在一台台灣版機器上，透過 `xiaomi_miot` 整合（本地 miIO 輪詢，UDP 54321）實測得到的觀察，
請當作觀察紀錄，不是規格。

MIoT 規格：<https://home.miot-spec.com/spec/chunmi.cooker.tw1>

## 用到的屬性與動作

| siid.piid / aiid | 名稱 | 備註 |
|---|---|---|
| 2.1 | 電鍋狀態 | 1 待機、2 烹飪、3 保溫、4 預約。HA 顯示 `idle` / `busy` / `keep warm` / `delay` |
| 2 / aiid 1 | start-cook（參數 piid 6） | **只接受 1～6**，見下表 |
| 2 / aiid 2 | cancel | `button.…_cancel_cooking` |
| 4.15 | cooking-data（字串） | 只寫；176 位元組食譜封包，見 [recipe-format.zh-TW.md](recipe-format.zh-TW.md) |
| 4.16 | bell | **千萬不要寫入** |
| 4.17 / 4.18 / 4.19 | status / phase / menu | menu 是 20 位元組的十六進位表頭，見下 |
| 4.20 / 4.21 | t-cook（分）/ t-left（秒） | |
| 4.30 | temp（°C） | 解析度 1～2 °C，本地輪詢約 30 秒 |
| 4 / aiid 1, 3 | set-start、set-menu（cooking-data） | 送完整的 176 位元組封包（表頭＋曲線＋CRC16/XMODEM）**有效**；較短或不合法的回傳 0 但被靜默忽略 |
| 4 / aiid 4 | set-factory-reset | **不要呼叫** |

整份規格裡**沒有目標溫度屬性**。

## `start-cook` 參數

| 參數 | 結果 |
|---|---|
| 1 | 精煮飯 |
| 2 | 快煮飯 |
| 3 | 煮粥 |
| 4 | 保溫（加熱到自己的平台約 73～75 °C 後維持） |
| 5 | 米家 App 的**「自選」格**：啟動 App 目前放在那裡的食譜（時間以 App 設定為準） |
| 6 | 再加熱（25 分，平台約 79～81 °C） |
| 7～15 | 被拒絕（−1） |

## `menu` 表頭

20 位元組，大多是 0。**最後一個位元組代表食譜**（前兩個位元組隨來源而變：`0404` 待機、`0303…04` 保溫、
`0505…` App 食譜、用參數 5 啟動時為 `0404…<位元組>`，剛啟動時可能短暫出現別的值）：

| 位元組 | 食譜 | 原廠時間 |
|---|---|---|
| 06 | 優格 | 360 分（App 可調） |
| 07 | 嬰兒粥 | 180 |
| 08 | 泡麵 | 20 |
| 09 | 蛋糕 | 60 |
| 0a | 煲湯 | 120 |
| 0b | 再加熱 | 25 |
| 0c | 關東煮 | 90 |
| 0d | 熱米飯 | 30 |
| 0e | 香甜煮 | 70 |
| 0f | 極速煮 | 30 |

## 實測溫度行為（鍋內有水）

| 程式 | 行為 |
|---|---|
| 優格（App） | 平台 **40～42 °C**，階段 1 → 8 |
| 保溫 | 平台 **73～75 °C**，階段 0，`t_left` 往上數 |
| 再加熱 | 平台 **79～81 °C**，階段 3 → 8 |
| 煮飯 | 煮滾（約 105 °C），階段 3 → 9，之後降溫 |
| 蛋糕 | 約 15 分鐘從 28 升到 101 °C（階段 3），之後階段 8、103～105 °C（仍在滾） |
| 泡麵 | 約 4.5 分鐘從 77 升到 105 °C（階段 3），煮滾（此食譜 `t_left` 往上數） |

原始的蛋糕與泡麵紀錄見 `../data/`。

## 試過但沒破解的

- **App 食譜編碼：已解開**（見 [recipe-format.zh-TW.md](recipe-format.zh-TW.md)）。是用 Frida 掛在 root 手機上的米家
  找到的；電鍋自己的外掛替每個表頭欄位命了名。早期嘗試被忽略，只是因為沒有加熱曲線。
- **加熱曲線**：每個階段的目標溫度（`b2`）與功率（`b4`）已解開；`b1` 可以跳過階段；`b5`、`b6`、`0x78` 在階段 0～2
  看不到作用（見 [recipe-format.zh-TW.md](recipe-format.zh-TW.md)）。曲線格式沒有公開文件（我們查過，python-miio 只有舊款
  Chunmi 的階段名稱）。
- `mitmproxy` 搭配使用者安裝的 CA 會被 App 拒絕；`adb logcat` 沒有有用資訊。
- 小米雲端 API 對這台裝置回 403，我們沒有嘗試繞過。
- MikroTik 路由器的硬體加速會讓同一個橋接埠內的裝置互傳流量看不到，所以區網監聽時手機和電鍋要接不同埠。

## 給貢獻者的想法

- 解開加熱曲線剩下的部分：14 位元組一塊的第二張表、`b1` 的確切意義，以及階段 3 之後（階段 1 保持時到不了，需要流程
  會經過它們的食譜）。
- 測試其他韌體／型號（`chunmi.cooker.*`）是否有更多 `start-cook` 參數。
- 查明偶發的「時間到沒有自己停」（看過兩次、無法重現）是否有原因，並驗證 80 °C 以上與數小時全程的恆溫。
