# 食譜（`cooking-data`）封包格式

[English](recipe-format.md) | **繁體中文**

米家電子鍋 mini（`chunmi.cooker.tw1`）如何編碼食譜、如何在 Home Assistant 裡**經區網本地**送出（不經小米雲端），
以及還沒解開的部分。

## 怎麼找到的

1. 在 root 的手機上執行米家 App（小米官方大陸版 11.9.x），用 Frida 掛在外掛的原生橋接。按下「開始」的瞬間，
   App 會用一個字串參數呼叫 MIoT 動作 `siid 4 / aiid 1（set-start）`：這個字串就是下面的封包，而且是明文。
2. 電鍋外掛（`mijia.chunmi.cooker.tw1`，純文字的 React Native bundle）裡有編輯封包表頭的類別
   （`CMCookProfile`），表頭每個欄位因此都有名字。
3. App **沒有加熱曲線的編碼器**。完整封包（含曲線）來自雲端的食譜資料；App 只改表頭並重算 CRC。

## 封包格式（176 位元組）

| 位元組 | 內容 |
|---|---|
| 0–19 | 表頭（見下） |
| 20–173 | 加熱曲線（見「尚未解開」） |
| 174–175 | 前 174 位元組的 CRC-16/XMODEM（多項式 0x1021、初值 0、不反轉、xorout 0），**大端** |

### 表頭

| 索引 | 欄位 |
|---|---|
| 0、1 | 裝置類型、小類型（`02 01`） |
| 2 | *index*：模式 1–4 保留原值（00–03）；食譜編號 > 4 時，App 立即開始用 `05`、存入收藏用 `04` |
| 3–6 | menu id，32 位元大端，即食譜編號（見下） |
| 7 | 旗標：bit7 自訂儲存、bit6 可預約、bit5 可設自動保溫。低 5 位元電鍋不理會 |
| 8、9 | 烹飪時間：時、分 |
| 10、11／12、13 | 時長上限／下限（時、分）。上限 > 下限才可調整 |
| 14 | bit7＝預約開關，低 7 位元＝幾小時後開始 |
| 15 | bit7＝自動保溫，低 7 位元＝再幾分鐘後開始 |
| 17、18 | 米種 id（16 位元） |
| 19 | 口味（軟硬） |

### 食譜編號（`data/recipes.json`）

| id | 食譜 | id | 食譜 |
|---|---|---|---|
| 01 | 精煮飯 | 09 | 蛋糕 |
| 02 | 快煮飯 | 0a | 煲湯 |
| 03 | 煮粥 | 0b | 再加熱 |
| 04 | 保溫 | 0c | 關東煮 |
| 05 | 燉煮 | 0d | 熱米飯 |
| 06 | **優格** | 0e | 香甜煮 |
| 07 | 嬰兒粥 | 0f | 極速煮 |
| 08 | 泡麵 | | |

## 從 Home Assistant 送出食譜

```yaml
service: xiaomi_miot.call_action
data:
  entity_id: sensor.chunmi_tw1_c3d7_cooker   # 你的電鍋
  siid: 4
  aiid: 1
  params: ["<176 位元組封包，352 個十六進位字元>"]
```

`tools/cookcode.py` 會組封包（改表頭並重算 CRC）：

```
python tools/cookcode.py list
python tools/cookcode.py show 優格
python tools/cookcode.py hex 優格 --minutes 360 --keep-warm off
python tools/cookcode.py hex 燉煮 --minutes 90 --order 60      # 60 分鐘後開始
```

卡片的**食譜**分頁在瀏覽器裡做同樣的事（JavaScript 版本，已與 Python 工具逐位元組比對）。
停止用 `button.…_cancel_cooking`。

真機驗證：原版封包會啟動對應食譜；改時長有效（優格設 300 分鐘 → `t_cook` 300）；精煮飯預約 3 分鐘 →
`t_pre` 3；表頭第 7 位元組不被檢查。

> **送出封包會立刻開始加熱。** 請確認內鍋有水或食材。

## 尚未解開的部分

第 20–173 位元組是加熱曲線：7 位元組一筆的表 `91 b1 b2 78 b4 b5 b6`（部分食譜後面還有 14 位元組一塊的第二張表）。
我們有 15 條完整曲線，並觀察到：

- 電鍋的 `phase`（階段）屬性跟著記錄索引走：泡麵曲線的第 2 筆含 `1e`（30），電鍋也確實在階段 0 → 3 之間等約
  30 秒。記錄是 `ff` 或其他空值時，該階段會被跳過。
- `b2` 看起來是**溫度（°C）**：優格曲線含 `29`（41）、`28`（40）、`55`（85），符合「殺菌後維持約 40 °C」；
  煮滾型食譜則含 `7d`（125）、`6e`（110）、`82`（130）、`78`（120），像是「不設限」的預設值。
- 第 3 筆的 `b1` 各食譜不同（泡麵／保溫 `5a`、燉煮 `54`、關東煮 `58`、再加熱 `2b`、蛋糕 `66`），
  但**實測加熱速率與它無關**，所以不是功率。確切意義尚未確定。
- 重現實驗的提醒：`temp` 屬性是內鍋底下的熱敏電阻，加熱中或剛加冷水時讀數會遠高於水溫，請看趨勢，
  不要看單一讀數。

因此**不支援修改曲線**；只有表頭（時間、預約、自動保溫）可以安全修改。歡迎提交解開曲線的 PR。

## 法律／倫理

這是對作者自己擁有的裝置所做的互通性研究。`data/recipes.json` 內的封包是小米為這台電鍋提供的食譜資料，
收錄只為了能在本地控制電鍋；不含任何小米程式碼。與小米無關。
